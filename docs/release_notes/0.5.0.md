# 0.5.0

## 简体中文

### 新增功能

- **设备健康指标**：支持 `device_metrics` 上报和 `POST /api/device/metrics` 查询，供设备页面展示 CPU、内存和负载历史。支持按时间查询、时间戳去重及设备离线后的历史读取。
- **LLM Relay**：新增 `llm-execute`、`llm-cancel` 和 `llm-close` 接口。优先向运行发起端投递执行请求；重连时只重放尚未结束、尚未过期的请求，取消或关闭后停止重放。

### 兼容性调整

- 工具调用在设备重连后保留同一 request ID，向原设备和连接最多重发三次，等待时间为执行超时加 45 秒恢复窗口。重发不保证工具仅执行一次。
- Agent 空闲看门狗从初始化时启动，普通运行使用固定 30 分钟窗口，异构 Agent 使用 60 分钟窗口，后端活动会刷新计时。
- 协议基线更新至 Device Gateway `b0bbeab` 和 Agent Gateway `2986083`。

### 运行约束

- 设备健康历史仅保存在内存中，最多保留 48 小时。上限为每设备 3,000 条、全局 300,000 条及 1,000 个设备历史；超限时淘汰旧数据，重启后历史丢失。
- 工具调用恢复可超出通用 HTTP 写入超时，反向代理需允许相应等待时间；默认总等待时间为 75 秒。
- 保持单实例、无外部依赖。不支持 Workspace 共享设备、管理 API、网关管理指标及上游标记为 alpha 的实验室功能；设备健康指标属于支持范围。

## English

### Added

- **Device health metrics**: added `device_metrics` uploads and `POST /api/device/metrics` queries for CPU, memory, and load history on the device page. Supports time-based queries, timestamp deduplication, and history reads while devices are offline.
- **LLM Relay**: added `llm-execute`, `llm-cancel`, and `llm-close` endpoints. Execution requests prefer the client that started the run; reconnect replay includes only open, unexpired attempts and stops after cancellation or close.

### Compatibility

- Tool calls retain the same request ID across device reconnects, with up to three retransmissions to the original device and connection. The wait covers the execution timeout plus a 45-second recovery window. Retransmission does not guarantee exactly-once tool execution.
- The Agent inactivity watchdog starts at initialization, with a fixed 30-minute window for regular runs or 60 minutes for heterogeneous agents. Backend activity refreshes the timer.
- Protocol baselines updated to Device Gateway `b0bbeab` and Agent Gateway `2986083`.

### Runtime constraints

- Device health history is held only in memory for up to 48 hours. Limits are 3,000 samples per device, 300,000 samples globally, and 1,000 device histories. Old data is evicted under capacity pressure, and restart loses the history.
- Tool-call recovery can exceed the generic HTTP write timeout. Reverse proxies must allow the corresponding wait; the default total wait is 75 seconds.
- Remains single-instance with no external dependencies. Workspace shared devices, admin APIs, gateway management metrics, and Labs features marked as alpha by upstream are not supported; device health metrics are supported separately.
